# calendar-summary

Companion to daily-generator (full-stack version) and morning-agenda (forward-looking briefing).

You are running the `calendar-summary` skill. Your job: write a single sidecar markdown file at `Daily/YYYY-MM-DD.calendar.md` in the vault, summarizing today's calendar events and today's sent email.

This skill is mechanical. Do NOT add prose summaries. The file is a raw snapshot the owner can review and merge into the real Daily file at end of day.

**Connectors.** This plugin ships no calendar or email access. Use whatever calendar connector (a tool that lists events for a date range) and email connector (a tool that searches sent mail) are available in this session. If one is missing, say which, write its section with the `[!todo]` line below, and continue.

---

## Step 0, Resolve paths and date

- Vault root: the `SECOND_BRAIN_VAULT` environment variable (`echo "$SECOND_BRAIN_VAULT"`). If it is unset or not a folder, say so and stop; never guess a path.
- Output folder: `Daily/` in the vault.
- Today's date: get via `date +%Y-%m-%d` (local time on this machine).
- Output target: `Daily/<today>.calendar.md` (always overwrite; this is a snapshot, not a draft the owner edits)

---

## Step 1, Gather data sources

Run these in parallel where possible. Each source is independent; if one fails, drop it and continue.

### 1a. Calendar (today)

Call the calendar connector's list-events tool with today's date range (00:00 to 23:59 local). Capture:

- Event title
- Start time (display in local timezone)
- Attendees (if any)
- Location or video link (if useful)

**Interpreting the response** (the shapes below are Google Calendar's; adapt to your connector):

- **Response has an `events` array**: render those events normally.
- **Response is calendar metadata (`{accessRole, summary, timeZone, updated}`) with NO `events` key**: this is the API's "zero events" signal, not an error. The day is genuinely empty. Write `- (no events today)` and do NOT include a `[!todo]` callout.
- **Response is an error object or the call throws (auth, connection)**: write `> [!todo] Calendar connector error: <details>` in the Meetings section.

### 1b. Sent email (today)

Call the email connector's search tool for mail the owner sent today (for Gmail, the query `in:sent after:<today>`). Summarize each as: `to <recipient>, subject "<subject>"`.

If the call fails or returns an auth error, mark the email subsection with `> [!todo] Email not connected this run` and continue.

---

## Step 2, Compose the file

Use this exact template. Fill the two sections; leave the YAML fixed.

```markdown
---
title: "Calendar snapshot {{DATE}}"
type: calendar-snapshot
date: {{DATE}}
captured: {{TIMESTAMP}}
tags: [type/calendar-snapshot, source/calendar, source/email]
---

# Calendar snapshot, {{DATE}}

> [!info] Auto-generated by `calendar-summary`. Not the canonical Daily file. Merge useful entries into `Daily/{{DATE}}.md` if you keep one.

## Meetings

<calendar entries here>

## Log (today's sent email)

<sent email entries here>
```

Format calendar entries as:

```
- **<HH:MM>**, <Event title>, attendees: <comma-separated>
    - <location/link if relevant>
```

Format sent email entries as:

```
- to <recipient>, subject "<subject>"
```

If a section is genuinely empty, write the placeholder line ("(no events today)" or "(no sent email today)").

---

## Step 3, Write the file

Use the `Write` tool. Path is `$SECOND_BRAIN_VAULT/Daily/<today>.calendar.md`. Overwrite if it exists; this is a snapshot.

---

## Step 4, Report back

Tell the owner:

1. The file path written.
2. Counts: N calendar events, M sent emails.
3. Which sources were unavailable this run (calendar, email) so they know what to fill in themselves.

If anything failed unexpectedly, name the failure mode specifically.

---

## When NOT to use this skill

- For the full daily file (calendar + email + project commits + skeleton sections), use `daily-generator` from Claude Code.
- For forward-looking briefings, use `morning-agenda`.
- When the owner says "what did I do today", use `daily-generator` instead (richer output).

---

## Schedule

This skill suits a daily scheduled task at end of day. From a sandboxed surface that cannot see project folders, it is the right end-of-day capture; `daily-generator` needs filesystem access to the repos it scans.
